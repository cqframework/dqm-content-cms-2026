# CQMElementsTests test cases

Test data for the `CQMElementsTests` CQL library, evaluated by the CQL VS Code extension
(`CQL: Execute`). Each subfolder is one patient context (**`Patient.id` must equal the folder
name**); results are written to [../results/CQMElementsTests.txt](../results/CQMElementsTests.txt).

Every test expression is evaluated for every case. A case test lists its expected result for
each case it covers and is `true` for the others, and invariant tests (marked in the library)
must hold for every case. So every test must be `true` for every case:

- `true`: passed (or the test doesn't cover this case)
- `false`: failed
- `null`: failed; the assertion couldn't be evaluated, e.g. because an element it reads came
  back null

To check a run, including that every case name used in the tests is one of the case folders:

```
python .claude/skills/cql/check_results.py CQMElementsTests
```

[CQMElementsTests.zip](CQMElementsTests.zip) packages these cases for import into MADiE: one folder per case, each
holding a single collection Bundle of the case's resources. Rebuild it after changing the data:

```
python scripts/make_test_case_zip.py input/tests/CQMElementsTests
```

The data was generated by a script, but the JSON files are the source of truth; edit them
directly.

**Terminology.** The retrieves and the `edVisit()` / `observationVisit()` /
`outpatientSurgeryVisit()` functions test value set membership, so they use the VSAC
expansions in `input/vocabulary/valueset/external/`. Each code below has been checked against
its expansion.

## Observations for review (not test failures)

1. **`Hospitalization Encounters` doesn't filter by status.** It groups whatever encounters it is
   given, so a cancelled encounter in the input becomes part of the hospitalization (case 04:
   `hospitalization()` would start at the cancelled ED visit). `edVisit()` and the other visit
   functions do check `status = 'finished'`, and `All Encounter Location Entries` /
   `All Encounter Locations` pass every retrieved encounter, cancelled ones included.
   `TestHospitalizationEncountersFilteredInput` shows the expected usage, passing only the
   finished encounters from the CQMElements retrieves.
2. **Arrival time can be later than admission time.** `hospitalArrivalTime()` reads the first
   location, while `hospitalAdmissionTime()` reads the first encounter. When the first
   encounter has no locations (case 03), arrival is later than admission.

3. **Query `return` removes duplicates — fixed.** `hospitalizationLocations()` and the `location`
   of a normalized encounter were built with `flatten (... IE return IE.location)`, so two included
   encounters with identical location lists would have been reduced to one. Both now use
   `return all`.

## Confirmed on the first run

- `~` on FHIR structures (`period`, `type`, `location`) works as expected.
